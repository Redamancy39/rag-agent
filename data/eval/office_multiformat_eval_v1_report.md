## 4. 关键发现

1. DOCX 段落、PPTX 幻灯片、XLSX 工作表及单元格范围均能进入引用结果。
2. XLSX 行事实切块效果最好，数值类问题和跨行聚合基本可用。
3. PPTX 普通文本检索稳定；复杂二维表格经过 LLM 结构化后效果明显更好。
4. 拒答题正确返回“未找到”，没有使用模型常识补全。
5. 首轮 15 题约耗时 94 秒，平均约 6.3 秒/题。
6. ChatLog 只保存答案和引用，没有保存 retrieval trace 和 evidence decision，
   不利于复盘偶发失败。

## 5. 已修复问题

LangGraph 入库路径原先直接采用 Agent 的 LLM 建议，未尊重上传时的关闭开关。
这导致含表格的 DOCX/PPTX 即使选择关闭，仍执行 LLM 处理。

修复后：

- Agent 负责给出建议；
- 用户开关和系统配置负责最终裁决；
- Parse/OCR、路由节点和 Normalize 节点使用同一个有效配置；
- 含 8 个表格的 DOCX 关闭 LLM 后实测约 2 秒完成；
- 未生成 LLM 结构化切块；
- 相关 11 项单元测试全部通过。

## 6. 下一步建议

1. 将 retrieval trace、query plan、evidence decision 持久化到评测结果或 ChatLog。
2. 对同一实体跨多行的 XLSX 问题增加 group key 聚合，例如按样品名称和抽样编号聚合。
3. 将表格 LLM 整理设置为按质量分触发，而不是发现表格就全部处理。
4. 修正前端阶段文案，区分“Agent 建议使用 LLM”和“最终实际启用 LLM”。
5. 用相同测试集分别执行 LLM 开启/关闭的 A/B 测试，量化准确率、耗时和 API 成本。
