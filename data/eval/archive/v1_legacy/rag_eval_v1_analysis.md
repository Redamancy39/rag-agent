- 失败：19

## 失败类型

### 1. 评测脚本过于严格，但答案基本正确

这些问题主要是字符串格式问题，不一定是 RAG 失败：

- `Q006`：答案为 `5×10^3`、`5×10^4`，期望为 `5×10³`、`5×10⁴`。
- `Q014`：答案为 `M=100 CFU/g`，期望关键词为 `10²`。
- `Q016`：答案为 `无焦斑和霉斑`，期望关键词为 `无霉斑`。
- `Q022`：答案为 `GB2716`，期望关键词为 `GB 2716`。
- `Q036`：答案为 `10^2`、`10^3`，期望为 `10²`、`10³`。
- `Q058`：答案为 `GB4806.9`、`GB4806.12`，期望为带空格的 `GB 4806.9`、`GB 4806.12`。
- `Q059`：答案为 `GB5749`，期望为 `GB 5749`。

建议：评测脚本增加归一化规则，把上标、`^` 指数、标准号空格、全角半角、大小写、`100` 与 `10²` 做规范化后再匹配。

### 2. 答案正确但期望关键词可能过宽

- `Q009`：问题问“预包装食醋标签应标示什么含量”，回答“总酸含量”是直接答案；期望关键词还要求 `甜醋`，这个关键词来自表2理化指标，不一定是该问题的必要答案。
- `Q041`：问题问海水鱼和淡水鱼分别是多少，系统回答 `30 mg/100g` 和 `20 mg/100g`；期望还要求 `25`。如果 `25` 是其他水产品类别，应拆成另一题或修改问题表述。

建议：把评测分为“必要关键词”和“可选关键词”，不要把背景表格中的非答案字段都设为必选。

### 3. 入库/解析质量导致真正未找到

这些是优先修复对象：

- `Q026`：兽药 OCR 表格命中页码正确，但模型仍判断未找到。原因可能是 OCR 表格行列关系不够清晰，`不 得 检 出` 或项目名与数值没有稳定绑定。
- `Q040`、`Q054`、`Q060`：蜂蜜 `GB 2730` 相关问题未命中或命中错误文档，可能是该文档未入库、状态异常、权限不可见，或对应页切块质量过低。
- `Q043`、`Q044`：植物油 `GB 2716-2018` 命中了文档，但切块中出现韩文/乱码样字符，说明 PDF 文本层或 OCR 结果污染，导致 LLM 结构化事实错误。
- `Q052`：兽药磺胺类问题命中了相邻表号 `表34`，期望 `表35`，说明长表格/连续条款的页内定位仍不够稳定。
- `Q048`：蛋制品微生物限量中指数被识别错，例如 `10`、`106`、`5×101`，属于表格指数/OCR 排版错误。

建议：对这些文档优先使用“文档列表 -> LLM整理”，并人工查看质量报告中的低质量块、OCR 块和 LLM 归一化块数量。植物油和蜂蜜建议重新入库时开启 OCR fallback 和 LLM 整理。

## 下一步建议

1. 先改评测归一化，避免把格式差异误判为失败。
2. 对 `GB 2716-2018 植物油.pdf`、`GB 2730 蜂蜜.pdf`、`GB 31650.1-2022 食品中41种兽药最大残留限量.pdf` 单独查看切块质量。
3. 对这些文档执行手动 LLM 整理，重点观察新增的 `llm_normalized_chunk` 是否包含页码、表号、项目、限量值和单位。
4. 对兽药和微生物限量类表格，后续应增加“表格行列专用解析器”，不要只依赖 OCR 行文本和通用 LLM 整理。
