# 食品热词与提问纠错

第一版范围：通用食品安全，48 个术语（添加剂 16、污染物 14、微生物 10、检测指标 8）。术语拼写来源为国家卫健委食品安全国家标准目录及官方问答；这里只引用术语，不保存法定限量、使用许可或标准有效性判断。问答结论仍以账号有权检索的文档为依据。

## 使用

在知识问答输入问题，停顿约 450 ms 后执行本地预检。明确配置的错字会显示“原词 → 标准词”和检索问题；例如“菌落总树”纠正为“菌落总数”。仅拼写相似的词提供“采纳”按钮，例如“大肠杆群”建议“大肠菌群”，发送前未采纳就保持原词。热词表可折叠展开，支持按类别、术语、简称和错字搜索；普通账号和管理员均可查看。

原始输入保存在会话历史；查询计划保存 corrected_question、normalized_question、corrections、suggestions、hotword_matches、lexicon_version。回答上方显示本次纠错，在“检索与证据判断过程”中查看检索问题和词表版本。旧历史不补造检测记录。

## 流程与边界

原始问题 → 本地热词检测 → 配置的错字替换 → 简称/同义词归一化 → 既有 QueryAgent 规则规划 → 权限过滤后的混合检索/重排 → 证据判断与回答。预检与正式规划共用 query_preview，预检不访问文档、创建任务、写历史或调用 LLM。正式问答在得到查询计划后，用 corrected_question 做回答和证据判断，日志仍保留原始输入；简称扩展只用于检索，不把食品类别或不同指标视为同一业务对象。

确定纠错仅限人工配置的 typos；编辑距离不会自动改问题。第一版近似建议仅考虑 4 字以上中文术语的一字替换，最多显示 5 组、每组 3 个候选，不声称覆盖所有错字。不进行任意问题语义重写。现有可选 LLM planner 的开关保持原样，当前启动配置默认关闭，不为此模块增加付费调用。

保护完整已知词、标准号、数字、单位、URL、文件名与拉丁/数字后缀。不把硝酸盐改成亚硝酸盐，不把钾盐改成钠盐，不把 B1 改成 M1；不把“大肠杆菌”当成“大肠菌群”。Unicode 建议位置用码点计数，前端采纳时校验当前原问题和候选，过期建议不会覆盖新输入。

原有 query_synonyms.py 的 3 组同义词与检索规则继续保留，其中山梨酸的既有扩展是检索分组；不据此把山梨酸和钾盐的实际使用条件合并。词表不从全部私有文档自动抽取，避免越权透露文档术语。

## 维护

词表：backend/app/agent/food_hotwords.json。修改时补全 term、category、aliases、typos、source，并增加 version。来源用于核对标准词；别名与错字映射属于人工维护的应用配置，不能把来源页当成所有纠错映射的证明。首次修改后运行后端测试，确认队列空闲再通过已有启动脚本加载；运行中词表缓存不会自动改变已提交问题的规则。前端当前为只读搜索表，不包含管理编辑接口。

同一错字不能指向多个术语，已知有效词不能登记为自动错字。有语义歧义的变体不要加入 typos；作为建议由用户采纳。当前基础词表不是穷尽词典，后续根据人工确认的实际错误逐步补充。

## 验证（2026-10-09）

仅使用合成问题、模拟模型与隔离数据库。后端覆盖确定纠错、重复词位置、相近但不同的指标、简称、URL/文件名/后缀保护、预检与真实计划一致、可选 planner 回退、回答使用纠正后的问题而历史保留原文，以及普通账号访问与未登录拒绝。前端覆盖 Unicode 位置、过期建议、非候选拒绝，并完成类型检查、构建和普通账号合成 UI 验证。后端与前端测试命令见根 README；本机激活报告留在忽略的运行目录。
