# 从 Agent Py 借鉴的后续计划

记录日期：2026-10-10

后续改动直接在本仓库进行，不把 Agent Py 后端并进来，也不新建一套项目。Agent Py 只作为对照：`E:\agent_py-release-2026-09-08`。

本仓库继续作为知识库产品。入库探测、文本 / PaddleOCR / LiteParse 分流、文档集与部门权限、热词、同义词、查询规划和证据不足时拒答都保留。Chroma、SQLite 和现有 BGE 模型也不替换。

## 要做

1. **独立登录页。** 现在登录状态在 `frontend/src/App.vue` 内切换。改成工作台外的登录和注册页面，未登录不能进入文档、问答和权限界面。参考 Agent Py 的 `/login`、`/register` 与登录后的工作台路由。不要把 Agent Py 的诊断页和 MCP 页一起搬过来。

2. **Agentic RAG。** 模型先决定要不要查库。要查时，继续使用本仓库的查询规划、热词、同义词、混合检索和证据判断。这不是只加一个“查或不查”的分类器，也不是用 Agent Py 的固定检索管线替换现有问答链。Agent Py 的检索工具还会并列当前时间、Skill 和 MCP；本仓库第一阶段只需要把知识检索变成可选工具，查中之后仍走现有 RAG 链路。

3. **会话记忆。** 对话变长后再做。按会话保留完整历史，并支持每 30 轮、上下文约 70% 或手动压缩。压缩只生成摘要，不删除原消息。

4. **Skill。** 放在记忆之后。用它规定某类任务的步骤、输出结构和格式，而不是再做一个“是否启用整段提示词”的开关。Agent Py 当前是用户勾选允许名单，模型再调用 `load_skill` 读取正文；本仓库若采用，优先让已启用 Skill 的目录交给模型判断。食品安全问答已有证据和引用约束，Skill 不是主链路的前置条件。

## 不做

- 不迁入 Agent Py 的智能诊断。那是从 Prometheus 或 Alertmanager 告警出发的计划、执行和报告，不属于当前知识库主链路。
- 不迁入 `/aiops`、`/mcp` 页面，也不为了 CLS 日志改当前启动方式。
- 不删除入库路由。文本层、OCR 兜底和 LiteParse 的分流继续保留。
- 不把向量库从 Chroma 换成 Milvus，也不把权限模型退回到只有用户隔离。

## 建议顺序

1. 独立登录页和路由守卫。
2. 问答改为模型选择是否调用检索；检索命中后仍走现有规划、混合召回和证据判断。
3. 会话记忆压缩。
4. Skill 形式的任务输出规范。
